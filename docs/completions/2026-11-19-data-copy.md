## 3. Stakeholder decisions applied

### Q1 — Duplicates: skip exact name+email pairs

**Rule:** keep the lowest `ParticipantID` per exact `(LastName, FirstName, Email)`; skip the rest. Rows with no email are always kept.

| | |
| --- | --- |
| Duplicate groups found | **32** |
| Participant rows skipped | **32** (14,435 → 14,403) |
| Registrations **reassigned** to survivor | **79** |
| Audit records written | 79 in `audit.ChangeLog` (`ChangedBy = 'etl:dedupe'`) |
| Duplicates remaining in target | **0** |

**Important:** skipping a participant row would have orphaned 79 registrations. Those were reassigned to the surviving participant **before** the duplicate was dropped, so no registration history was lost.

**A note on the count.** An earlier case-sensitive check found 29 groups. The transform matches case-insensitively (`Kenyajones0307@` = `kenyajones0307@`), which is correct for email, and finds **32**. The 3 extra groups are genuine case variants.

### Q3 — Workshop-less registrations: "Legacy workshop"

| | |
| --- | --- |
| Registrations with no workshop | **78** |
| Parent row created | `core.Workshop` ID **0**, `WorkshopNameID = 0` |
| Catalog row created | `core.WorkshopName` ID **0** — `WorkshopName = 'Legacy workshop'`, `ShortName = 'Legacy'` |
| Registrations attached | **78** |
| `NULL WorkshopID` remaining | **0** |

ID 0 is reserved in both tables and cannot collide with a legacy ID (legacy range is 1..1798 for `WorkshopName`, 1..3012 for `Workshop`). The workshop is `IsClosed = 1` so it will not appear as an open offering.

Because the catalog row exists, the label is now visible in any report that joins `Workshop → WorkshopName`:

```
WorkshopID=0  WorkshopNameID=0  Name='Legacy workshop'  Short='Legacy'  IsClosed=True
```

## 7. Issues encountered and fixed

**Transport-level connection drops.** The first extract died mid-transaction on `tblSessionParticipants` (~6,561 rows). Fixed by committing every 2,000 rows, adding exponential-backoff retry on transient errors, and making the loader resumable.

**Orphan check used the wrong ID.** The first transform tested the *original* `ParticipantID` when deciding what to quarantine, so the 79 registrations belonging to deduplicated participants were quarantined instead of reassigned. Fixed to test the *resolved* ID.

**Foreign keys silently dropped.** The transform's reset drops all FKs; only 2 were being re-added. Fixed by restoring all 75.

**Dangling references blocked FK creation.** `BoardMember`, `Registration.PayeeID`, `WorkshopSession`, `WorkshopPresenter` and `CreditSlip` all reference parents that do not exist. Fixed with the null-and-quarantine policy in §4.
